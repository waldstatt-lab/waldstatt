# 0002 — Make the Waldstatt a browser game that gates its content

**Amended by [ADR 0003](0003-save-the-waldstatt-in-indexeddb.md):** the
game state moved from `localStorage` to an IndexedDB database of its own,
`waldstatt-games`. The rules below for storage (untrusted input, a reset that
touches only the Waldstatt's data) apply to it unchanged.

## Context

The [pitch](../../pitches/pitch--aufbauspiel-im-wald.md) turns the
website into a building game: the home page is an endless forest, and visitors
unlock the site's content by felling trees and building. The studio chose a
strict gate: content is reached only through play, the about and game pages are
removed, and there is no text fallback. This breaks what
[ADR 0001](0001-build-a-static-site-with-astro-and-daisyui.md) set for the site:
no server, database or client-side JavaScript, and pages of plain HTML and CSS.

A game whose state must survive reloads needs storage, and an endless,
changing forest with thousands of sprites is beyond a small hand-written canvas
script.

Alternatives considered for the content gate:

- **A playable home page beside plain archive pages.** Keeps 0001 intact for the
  content, but makes the game optional decoration. The studio rejected it.
- **Play only, with a `<noscript>` summary.** Rejected for the same reason.
- **Play only, with no fallback.** Chosen.

Alternatives considered for rendering:

- **Native Canvas 2D.** No dependency, but batching, culling and texture
  management for an endless forest would have to be written by hand.
- **PixiJS (WebGL 2D).** GPU sprite batching, culling and textures; one npm
  dependency of a few hundred kilobytes on the game's page only.
- **Babylon.js.** A 3D engine for a 2D map.
- **Bevy compiled to WebAssembly**, the games' engine. Megabytes of download and
  a slow start for a home page, a Rust toolchain in CI, and text drawn on a canvas
  instead of HTML.

## Decision

- The home page is a game that needs JavaScript and WebGL. Its content, the
  studio texts, the shared game texts and the play and source links, is revealed
  only through play. `/ueber-uns/` and
  `/spiele/<spiel>/` do not exist. Without JavaScript or WebGL,
  the page shows a still picture, the name and a note, with no content or links.
- The content stays real HTML. Astro renders the texts at build time into inert
  `<template>` elements, and the script clones them into HTML panels over the
  map; it sets no HTML from strings.
- The map is rendered with PixiJS 8, bundled from npm through Astro and served
  from the site. The panels, menus and toolbox are HTML styled by the site's
  theme.
- The game state is one versioned JSON document in `localStorage` under keys
  starting with `waldstatt-games/`. It is validated as untrusted input, and
  resetting removes only those keys.
- The waters on the map are real: `src/waldstatt/tools/waters.mjs`
  generates them from swisstopo and BAFU data while developing, and the site
  never contacts swisstopo.
- A web manifest and a service worker make the game installable and
  playable offline. Both are generated by endpoints in
  `src/pages/`, and the worker's scope is
  the base path. It caches only that build's files.

The game makes no network requests other than for the site's own files,
handles keys only inside focused widgets or the focused map, and honours
`prefers-reduced-motion`.


## Consequences

- The site can be a real game, and the name's story, people clearing a forest,
  becomes something visitors do.
- Search engines, visitors without JavaScript or WebGL, and most screen-reader
  users cannot reach the site's content. This is accepted: the site is a
  game.
- The about and game pages are gone, and the architecture documentation has
  to say so.
- One dependency, PixiJS, enters `package.json` and needs updates like any
  other.
- The organization's Pages sites share an origin and thus `localStorage`. The
  key prefix, and a worker scope no wider than the base path, keep the
  Waldstatt from touching the games' saves or other pages.
- A service worker can serve a stale build. Cache names follow the build, and the
  page is fetched network-first.

## The tell

- `rg -n "localStorage|sessionStorage|indexedDB|serviceWorker" src` finds
  matches only in `src/waldstatt/`; every Waldstatt key starts with
  `waldstatt-games/`, and its only database is `waldstatt-games`.
- `rg -n "from \"pixi.js\"" src` finds imports only in
  `src/waldstatt/`.
- `ls src/pages/` shows `index.astro` and the manifest and
  worker endpoints, with no `ueber-uns.astro` and no `spiele/`.
- `rg -n "localStorage.clear" src` finds nothing.

A search cannot show that the worker's scope stays narrow or that a reset leaves
the games' saves alone. Check both by hand in the browser's application panel
after playing a game and resetting the forest.
